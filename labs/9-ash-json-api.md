# Lab 9 - AshJsonApi

## Relevant Documentation

- [AshJsonApi Docs](https://hexdocs.pm/ash_json_api/getting-started-with-ash-json-api.html)

## Existing Setup

- JSON API router created
- Bearer authentication loaded in the API pipeline

## Steps

1. Loading a bearer token assigns the user to the connection, but Ash APIs read
   their actor through `Ash.PlugHelpers`. In `TwitterWeb.Router`, add this after
   `plug :load_from_bearer` in the `:api` pipeline (`set_actor/2` comes with
   `use AshAuthentication.Phoenix.Router`, like `load_from_bearer`):

```elixir
plug :set_actor, :user
```

This ensures actor-aware policies and calculations see authenticated API users.

2. Add `AshJsonApi.Resource` to the extensions to `Twitter.Tweets.Tweet`

```bash
mix ash.extend Twitter.Tweets.Tweet json_api
```

The generator also inserts a `json_api do type "tweet" end` block into the
resource — extend that block in the next step rather than adding a new one.

3. Add an `index` route

```elixir
json_api do
  type "tweet"

  routes do
    base "/tweets"

    index :feed
  end
end
```

4. Make sure the server is running (`mix phx.server`) and that you have created
   a few tweets, then visit `localhost:4000/api/json/tweets`. You might notice
   that the `attributes` key is empty. This is because we haven't marked any of
   our attributes as `public?`.

For an API extension to show any attributes, calculations, or aggregates, they
must be marked `public?`. Add the `public? true` option to the attributes on the
`tweet` (including the timestamps), and to the `like_count` aggregate:

```elixir
count :like_count, :likes do
  public? true
end
```

Refresh the endpoint and the attributes appear, but `like_count` still doesn't.
`public?` makes a field _available_ to the API, but by default AshJsonApi only
serializes public attributes. Aggregates and calculations have to be requested
explicitly with a sparse fieldset, which we'll do in step 6. If you want them in
every response, list the fields in the `json_api` block with
`default_fields [:text, :inserted_at, :like_count]`.

5. You'll notice also that the `links` are empty. We can add a `get` route to
   fetch a tweet.

```elixir
get :read, primary?: true
```

This `primary? true` causes the `links` to use this route as the `self` link for
any given tweet.

6. JSON APIs typically use `camelCase` field names, but our attributes are
   `snake_case`. Add `field_names :camelize` to the `json_api` block and refresh
   the endpoint — fields like `like_count` are now serialized (and accepted in
   filters, sorts, and sparse fieldsets) as `likeCount`.

```elixir
json_api do
  type "tweet"
  field_names :camelize

  # ...
end
```

Try requesting just that field:
`localhost:4000/api/json/tweets?fields[tweet]=likeCount`.

### Try on your own

- Try out the api at `localhost:4000/api/json/tweets`
- Check out the swagger docs at `localhost:4000/api/json/swaggerui`
- Check out the redoc docs at `localhost:4000/api/json/redoc`
- Add `hide_fields [:updated_at]` to the `json_api` block. Unlike `public?`,
  which controls whether a field is available to API extensions at all,
  `hide_fields` hides an already-public field from this JSON:API interface
  specifically. (It only accepts public fields — hiding a non-public field like
  `user_id` won't compile.)
- Add a `description` to one of the attributes to see how it populates in the
  autogenerated documentation.
- Add a `description` to the action, and to the resource as well.

**_TIP_**: For resources, the `description` is added inside of the `resource`
block.

```elixir
resource do
  description "your_description"
end
```
